Migrations · Seeders

Migrations

Migrations live in site/migrations/ with timestamped filenames: <TIMESTAMP>_<name>.php (e.g. 2025_01_15_120000_create_users_table.php).

Skeleton

use AuraCore\Migration;
use AuraCore\Schema;

class Migration_CreateUsersTable extends Migration
{
    public function up()
    {
        Schema::create('users', function ($t) {
            $t->increments('id');
            $t->string('name');
            $t->timestamps();
        });
    }

    public function down()
    {
        Schema::drop('users');
    }
}

Tracking

A migrations(id, migration, batch, executed_at) table is auto-created on first run. Each migrate writes a new batch number.

CLI commands

php aura migrate Run pending migrations. php aura migrate:rollback Roll back the last batch. php aura migrate:status Show ran / pending table. php aura migrate:fresh Drop all tables and re-migrate (asks for confirmation). php aura migrate:reset Roll back all batches (asks for confirmation). php aura migrate:refresh reset + migrate.

These commands are also exposed in the management panel at /management/migrations with Run / Rollback / Reset buttons.

Seeders

Seeders live in site/seeders/ as <name>_seeder.php with class <Name>Seeder. They extend AuraCore\Seeder and implement run().

use AuraCore\Seeder;
use SiteModels\UserModel;

class UserSeeder extends Seeder
{
    public function run()
    {
        UserModel::create([
            'name'     => 'Alice',
            'email'    => 'alice@example.com',
            'password' => password_hash('secret', PASSWORD_BCRYPT),
        ]);

        $this->call(PostSeeder::class);
    }
}

CLI:

  • php aura db:seed — run all seeders
  • php aura db:seed --class=UserSeeder — run a single seeder (kebab-matches the filename)
  • php aura db:wipe — drop all tables (asks for confirmation)
