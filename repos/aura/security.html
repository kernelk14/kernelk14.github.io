Authentication

AuraCore\Auth is a lightweight session-based auth helper. The default model class is \App\Models\User; pass your own via $this->auth('UserModel') or $auth->setModel('UserModel').

API

attempt([$credentials]) Look up by email, verify with password_verify(), then login(). attemptById($id) Login without a password (useful for "remember me"). login($user) Store $user->getKey() in $_SESSION['auth_id']. logout() Unset and call session_regenerate(). user() Lazy-load the current user from the session. check() / guest() / id() Status helpers.

Passwords are read from the password column. Use password_hash($pw, PASSWORD_BCRYPT) when creating users and password_verify($pw, $hash) to check.

Example: login form

public function login()
{
    $data    = $this->request()->only(['email', 'password']);
    $auth    = $this->auth('UserModel');

    if (!$auth->attempt($data)) {
        return $this->back()->withErrors(['email' => 'Invalid credentials']);
    }

    $this->redirect('/dashboard');
}

public function logout()
{
    $this->auth(\SiteModels\UserModel::class)->logout();
    $this->redirect('/');
}

Validation

Rules are pipe-separated strings. Each rule becomes a rule<Name>($field, $value, $params) method on the validator.

Built-in rules

RuleDescription
requiredValue must be present and non-empty.
emailValid email address.
min:nMinimum length (or numeric minimum for numbers).
max:nMaximum length (or numeric maximum).
numeric / integer / string / booleanType checks.
confirmedMatches the field_confirmation sibling.
same:otherMatches another field's value.
unique:table,column,ignoreId,ignoreColumnDB lookup (with optional self-exclusion).
url / alpha / alpha_num / alpha_dashFormat checks.
date / after:date / before:dateDate validation.
size:n / between:min,maxLength / range.

Validator methods

passes() Returns true if no rules failed. fails() Returns true if any rule failed. errors() Full error array ([field => [msgs]]). error($field) First error message for a field. errorBag() Flat list of all error strings.

Custom rules

Generate with php aura make:rule Uppercase. Custom rules live in site/rules/ (SiteRules\) and implement validate($attribute, $value, $params, $data) + message($attribute, $params).

Middleware

Class-based middleware with a handle($request, $next) method. Lives in site/middleware/ as kebab-case files, namespace SiteMiddleware\.

The Router builds a MiddlewarePipeline per request. The pipeline array_reduces the stack in reverse to build a chain of nested closures — each calls $middleware->handle($request, $next).

Example

namespace SiteMiddleware;

class Auth
{
    public function handle($request, $next)
    {
        if (!isset($_SESSION['user_id'])) {
            header('Location: /login');
            exit;
        }
        return $next($request);
    }
}

Wiring

// Per route
$router->get('dashboard', 'dashboard@index')->middleware('auth');

// Group — accumulates and attaches to every route inside
$router->group(['middleware' => ['auth']], function ($r) {
    $r->get('admin', 'admin@index');
});

Form Requests

Form-request classes encapsulate the validation of a single endpoint. Generate with php aura make:request StoreUserRequest.

They live in site/requests/ (SiteRequests\) and define:

  • rules() — returns the rules array.
  • messages() — custom error messages.
  • validate(array $data) — runs the rules and throws or returns the result.
  • authorize() — optional authorization gate.

Internally they use AuraCore\Validator.
